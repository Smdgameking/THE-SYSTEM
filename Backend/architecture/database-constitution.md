# Database Constitution

## Schema Management

- Flyway is the ONLY schema management tool
- Hibernate must never modify the schema (`ddl-auto=validate` only)
- All changes must be versioned and reviewed

## Naming Conventions

- Tables: snake_case (e.g., `user_roles`, `email_verified`)
- Columns: snake_case (e.g., `created_at`, `password_hash`)
- Indexes: `idx_<table>_<column>` or `uq_<table>_<column>`
- Constraints: `fk_<table>_<referenced_table>`

## Primary Keys

- Every business table uses UUID primary keys
- Generated by application (`UUID.randomUUID()`) or database (`gen_random_uuid()`)
- Never use auto-increment IDs

## Audit Fields

Every business table contains:
- `created_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
- `updated_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
- `created_by` UUID NULL
- `updated_by` UUID NULL
- `deleted_at` TIMESTAMP NULL (soft delete)

## Soft Deletion

- Use `deleted_at` TIMESTAMP NULL for soft deletion
- All queries must filter `deleted_at IS NULL`
- Never hard delete business data

## Indexes

- Index all foreign key columns
- Index frequently queried columns
- Unique constraints for business keys (e.g., email)

## Data Types

- UUID: `UUID` (PostgreSQL native)
- Strings: `VARCHAR(n)` with appropriate lengths
- Text: `TEXT` for unlimited length
- Timestamps: `TIMESTAMP` (not TIMESTAMPTZ, application handles timezone)
- Booleans: `BOOLEAN`
- Enums: Store as VARCHAR, not ordinal

## Migrations

- Filename format: `V<version>__<description>.sql`
- Each migration must be idempotent (`CREATE IF NOT EXISTS`)
- Never modify applied migrations
- Add indexes in the same migration as table creation
