# Decision Log

## 2026-08-07: Project Initialization

**Decision**: Use Modular Monolith architecture with Spring Boot 3.4.5 and Java 21.

**Rationale**: Long-term maintainability, clear module boundaries, easier transition to microservices if needed.

**Alternatives Considered**: Microservices from day one, Layered architecture.

**Consequences**: Clear module boundaries, but requires discipline to maintain.

---

## 2026-08-07: Database Schema Management

**Decision**: Use Flyway for all schema migrations. Set `ddl-auto=validate`.

**Rationale**: Production safety, version control for schema, no accidental modifications.

**Alternatives Considered**: Liquibase, Hibernate auto-DDL.

**Consequences**: Requires manual migration writing, but prevents production issues.

---

## 2026-08-07: UUID Primary Keys

**Decision**: Use UUID for all primary keys, generated by application.

**Rationale**: Distributed system friendly, no ID conflicts, better security.

**Alternatives Considered**: Auto-increment IDs, Snowflake IDs.

**Consequences**: Larger index size, but better for long-term scalability.

---

## 2026-08-07: Audit Fields

**Decision**: Every entity extends `BaseEntity` with audit fields.

**Rationale**: Consistent tracking, required for compliance and debugging.

**Alternatives Considered**: Database triggers, application-level interceptors.

**Consequences**: Slightly more complex entities, but consistent audit trail.

---

## 2026-08-07: JWT Authentication

**Decision**: Use JJWT library for JWT tokens with access/refresh token pattern.

**Rationale**: Industry standard, stateless, scalable.

**Alternatives Considered**: Session-based auth, OAuth2.

**Consequences**: Requires careful token management, but scales well.

---

## 2026-08-07: Security Configuration

**Decision**: Custom security config with stateless JWT, BCrypt passwords.

**Rationale**: Full control over security, no default Spring Security behavior.

**Alternatives Considered**: Spring Security defaults, OAuth2 Resource Server.

**Consequences**: More configuration, but tailored to project needs.

---

## 2026-08-07: API Response Format

**Decision**: Standardized response envelope with success, data/error, timestamp, requestId.

**Rationale**: Consistent client experience, easier error handling.

**Alternatives Considered**: Direct entity responses, HATEOAS.

**Consequences**: Extra wrapping, but consistent API contract.
